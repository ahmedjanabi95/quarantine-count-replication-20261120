# Site-specific guard calibration
On each site run one pinned Debian guest for calibration and evaluation. Use unmodified isolated benign probe workloads and policies from v11. Choose one deployment-wide timer before held-out acquisition, common to kernel and userspace datapaths and both burst sizes. Test 0, 50, 100, 200, 300 and 400 ms. The shortest candidate with 12/12 reference-eligible, dual-meter corroborated, correctly released counts across three schedule seeds and four conditions qualifies. If none qualifies, retain 400 ms as an unqualified fallback. Calibration and evaluation orders are shuffled separately and are identical across sites. Independent seed sets are defined in protocol.py. File frozen.json is written before evaluation.
Held-out: six unseen clean schedule blocks, four conditions, two arms (48 trials) plus one separate masked-witness block (eight trials). Account for all trials. Compare released correct, wrong and withheld counts first. Estimate paired guard-minus-check seal-to-deletion-barrier time averaging four conditions per complete clean seed and resampling whole seed blocks with replacement (percentile interval). Report polling cost and masked-witness outcomes separately. Never pool sites as independent hosts sampled from a population. Report all failed trials and zero-delay outcomes. Calibration is a finite engineering screen, not a statistical safety guarantee.
